# ระบบหลังบ้านโรงงานยาสมุนไพร (เว็บต้นแบบ ข้อมูลจำลอง)

> ⚠️ **ข้อมูลทั้งหมดเป็นของสมมุติ** ใช้สาธิตแนวคิดเท่านั้น ห้ามใช้บันทึกงานจริง เว็บนี้ไม่ใช่ระบบคอมพิวเตอร์ที่ผ่านการตรวจรับรองตามหลักเกณฑ์ GMP

เว็บต้นแบบให้เห็นภาพระบบหลังบ้านของโรงงานยาสมุนไพร ตั้งแต่รับวัตถุดิบสดจากเกษตรกร แปรรูป ปล่อยผ่าน เก็บเข้าคลัง ผลิต จ่ายออก จนถึงการขายและลูกหนี้
หัวข้อ ขั้นงาน ป้ายสถานะ และเลขที่ผลิต ยึดเอกสารของโรงงาน (ระเบียบปฏิบัติงาน SOP และแบบฟอร์ม FM) เป็นฐาน

## เปิดดู

เปิดผ่าน GitHub Pages ได้ทันที หรือเปิดในเครื่องด้วยเว็บเซิร์ฟเวอร์ (เปิดไฟล์ `index.html` ตรงๆ ไม่ได้ เพราะเว็บต้องโหลดไฟล์ข้อมูล)

```bash
python3 -m http.server 8000
# แล้วเปิด http://localhost:8000
```

## มีหน้าอะไรบ้าง

| แผ่นที่ | หน้า | ทำอะไรได้ | ยึดเอกสาร |
|---|---|---|---|
| 01 | ภาพรวมโรงงาน | ตัวเลขสำคัญ ผังกระบวนการแบบพิมพ์เขียว แจ้งเตือนอัจฉริยะ บอร์ดย่อ ยอดขายและลูกหนี้ | ร่าง KPI กลุ่มงานผลิต ตัวชี้วัด 2.1 |
| 02 | บอร์ดงาน | งานอยู่ขั้นไหน ในมือใคร ย้ายการ์ดทีละขั้น (ปุ่มหรือลากวาง) | SOP-PD-08 ถึง 25, SOP-QC-06, SOP-QC-07 |
| 03 | คลัง รับเข้า เบิกออก | คงคลังรายรายการ บัตรคุมวัสดุ รับเข้า เบิกออกแบบหมดอายุก่อนจ่ายก่อน (FEFO) | FM-01, FM-02, FM-19, FM-28 ถึง 33 |
| 04 | จัดซื้อ | ใบสั่งซื้อค้างรับพร้อมโอกาสมาทัน รายการที่ถึงจำนวนอย่างต่ำ ระยะส่งของจริงของผู้ขาย | FM-46 |
| 05 | ควบคุมคุณภาพ | คิวรอปล่อยผ่าน ปล่อยผ่านหรือไม่ผ่าน บันทึกการปล่อยผ่าน | SOP-QC-06, SOP-QC-07, FM-35 |
| 06 | ขาย ลูกหนี้ | ยอดขายรายเดือน ขายให้ใคร ลูกหนี้ตามอายุหนี้ ใบที่เกินกำหนด | FM-19 |
| 07 | ไล่ย้อนล็อต | ไล่ย้อนต้นทางถึงเกษตรกรหรือผู้ขาย และไล่ไปปลายทางเพื่อจำลองเรียกคืน | FM-07, FM-10 |
| 08 | ประวัติการแก้ไข | ทุกสิ่งที่ทดลองกรอก บอกว่าใคร ทำอะไร เมื่อไร เหตุผล | ระเบียบปฏิบัติงาน ข้อ 112 (ร่าง) |

**ลองเล่น:** เปลี่ยนผู้ใช้ที่มุมขวาบนเป็น ดาว ฝ่ายจัดซื้อและคลัง แล้วรับหลอดอลูมิเนียมตามใบสั่งซื้อที่หน้าคลัง จากนั้นเปลี่ยนเป็น แพร หัวหน้าฝ่ายควบคุมคุณภาพ ปล่อยผ่านล็อตนั้น แล้วเปลี่ยนเป็น เอ หัวหน้าฝ่ายผลิต เลื่อนงานครีมไพลที่หยุดรอหลอดบนบอร์ด
สิ่งที่ทดลองกรอกเก็บในเบราว์เซอร์เครื่องนั้นเท่านั้น ล้างได้ที่หน้าประวัติการแก้ไข

## กติกาที่เว็บบังคับ

- ของที่รับเข้าหรือผลิตเสร็จ ติดป้าย **รอปล่อยผ่าน** ทันที และเบิกไม่ได้ (ระเบียบปฏิบัติงาน ข้อ 77, WHO TRS 1025 ภาคผนวก 7 ข้อ 12.17)
- ป้ายเปลี่ยนเป็น **ตรวจสอบแล้ว** หรือ **ไม่ผ่าน** ได้โดย **หัวหน้าฝ่ายควบคุมคุณภาพ** เท่านั้น (SOP-QC-06, SOP-QC-07, ระเบียบปฏิบัติงาน ข้อ 89 และ 92)
- เบิกเรียงจากวันหมดอายุก่อน ถ้าวันหมดอายุเท่ากันใช้ล็อตที่รับก่อน (WHO TRS 1025 ภาคผนวก 7 ข้อ 12.30)
- เลขที่ผลิต 8 หลัก ประเภท ชื่อ ปีงบ ครั้งที่ (SOP-PD-07) ของที่ซื้อใช้เลขรับ `R` ปีงบ ลำดับ

## สูตรแจ้งเตือน (อยู่ใน `assets/logic.js` ไฟล์เดียว)

| ค่า | สูตร | ที่มา |
|---|---|---|
| สต็อกกันชน | Z × √(L̄·σd² + d̄²·σL²) | Gallego, Columbia IEOR 4000 (2004) ข้อ 1.3.1, King, APICS magazine (2011) |
| จำนวนอย่างต่ำ (จุดสั่งซื้อ) | d̄ × L̄ + สต็อกกันชน | MIT OCW ESD.260J (2006) บทที่ 11 |
| จำนวนอย่างสูง (ระดับเติมเต็ม) | d̄ × (R + L̄) + Z × σ(R+L) | MIT OCW ESD.260J (2006) บทที่ 12 |
| โอกาสที่ของที่สั่งแล้วจะมาทัน | Φ((วันที่ของหมด − วันที่สั่ง − L̄) ÷ σL) | หลักเดียวกับระดับบริการใน MIT บทที่ 11 |

d̄ กับ σd มาจากรายการเบิก 90 วันล่าสุด L̄ กับ σL มาจากประวัติส่งของจริงของผู้ขายรายนั้น

**ค่าที่ตั้งเอง รอเคาะ** อยู่ใน `assets/config.js` ไฟล์เดียว: ระดับบริการ 95% (สินค้าหลัก) และ 90% (รายการอื่น), เตือนใกล้หมดอายุที่ 90 และ 30 วัน, รอปล่อยผ่านเกิน 3 วัน, รอบทบทวน 30 วัน

## เปลี่ยนหน้าตา

สีและฟอนต์ทั้งเว็บอยู่ใน `assets/theme.css` สองบล็อกแรก (ธีม B1 พิมพ์เขียวพื้นขาว และโทนมืด) แก้ที่เดียวทั้งเว็บเปลี่ยนตาม

## ข้อมูลจำลองและทีมตรวจ

```bash
node tools/generate-data.mjs   # จำลองโรงงานย้อนหลัง 1 ปีทีละวัน เขียนไฟล์ใน data/
node tools/check-data.mjs      # ทีมตรวจข้อมูล: บัญชีคุมลงกัน ปล่อยผ่านก่อนเบิก FEFO เลขที่ผลิต ใบส่งของ (ต้องผ่าน 7 จาก 7)
node tools/test-flow.mjs       # ทีมตรวจการใช้งาน: ไม่ล้นจอมือถือและแท็บเล็ต สิทธิ์ตามบทบาท งานทั้งสาย (ต้องผ่าน 8 จาก 8 ต้องมี Google Chrome)
```

ข้อมูลทุกตัวมาจากเหตุการณ์ชุดเดียวกัน จึงลงกันทั้งระบบ เว็บเลื่อนวันที่ให้วันนี้ตรงกับวันอ้างอิงของข้อมูลทุกครั้งที่เปิด ฉากตัวอย่างที่ตั้งใจใส่ไว้ เช่น หลอดอลูมิเนียมที่ซื้อผ่าน e-bidding จะมาไม่ทัน ระบุไว้ใน `data/meta.json`

ไฟล์ข้อมูลเป็น CSV หนึ่งไฟล์ต่อหนึ่งตาราง หัวคอลัมน์ล้อผัง ERD ของงาน GM03 นำเข้า Google Sheets ได้ทันที

## ข้อจำกัดที่รู้แล้ว

- เว็บอยู่บน GitHub Pages ใครมีลิงก์ก็เปิดได้ จึงใส่ได้แค่ข้อมูลจำลอง
- การเลือกผู้ใช้เป็นการสมมุติบทบาท ไม่ใช่การล็อกอินจริง และประวัติการแก้ไขเก็บในเบราว์เซอร์ ผู้ใช้ลบเองได้
- ยอดขายและลูกหนี้ยังเป็นข้อมูลตั้งต้น ยังไม่ผูกกับการเบิกที่ทดลองกรอก
